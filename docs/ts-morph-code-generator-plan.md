# Convert Code Generator to `ts-morph`

## Goal

Rewrite `src/services/code-generator.ts` so that it builds the generated runtime file (`pac.runtime.ts`) and the generated config file using [`ts-morph`](https://ts-morph.com/) instead of hand-written string concatenation.

`ts-morph` wraps the TypeScript compiler API and provides:

- A typed, ergonomic builder API for JavaScript and TypeScript AST nodes.
- A built-in printer (`sourceFile.getFullText()`, `project.emit()`).
- Source map support if needed later.

This removes the need for both manual string rendering and for a separate Oxc + esrap pipeline.

## Motivation

The current `code-generator.ts` constructs TypeScript source by concatenating strings. This works for the current output but has drawbacks:

- Easy to produce syntactically invalid output when escaping, quoting, or indenting changes.
- Hard to extend with richer TypeScript features (generic helpers, complex types, class modifiers).
- No validation that emitted constructs are well-formed until the file is parsed or type-checked.

`ts-morph` solves these problems by making the generator operate on real TypeScript AST nodes and by printing them through the TypeScript compiler printer.

## Dependencies

Add `ts-morph` to `dependencies` in `package.json`:

```json
"ts-morph": "^25.0.0"
```

`ts-morph` is a self-contained package. It does not require `@babel/*`, `oxc-parser`, or `esrap`.

## High-level architecture

The public API of the `CodeGenerator` service stays the same:

```ts
export class CodeGenerator extends Context.Service<
  CodeGenerator,
  {
    readonly generateRuntime: (
      plan: Plan,
      eventDefinitions?: ReadonlyArray<EventDefinition>,
    ) => Effect.Effect<string, CodeGenerationError>;

    readonly generateConfig: (model: ImportModel) => Effect.Effect<string, CodeGenerationError>;
  }
>()("@app/CodeGenerator") {}
```

Internally, both methods create a `ts-morph` `Project`, build a `SourceFile`, and return `sourceFile.getFullText()`.

```ts
const project = new Project({
  manipulationSettings: {
    indentationText: IndentationText.TwoSpaces,
    quoteKind: QuoteKind.Single,
    useTrailingCommas: true,
  },
});

const sourceFile = project.createSourceFile("pac.runtime.ts");

// ... build the file using ts-morph API

return sourceFile.getFullText();
```

## Recommended file structure

Split the single file into focused modules:

```txt
src/services/
  code-generator/
    index.ts          # Effect service wiring and public API
    runtime.ts        # generateRuntime implementation
    config.ts         # generateConfig implementation
    helpers.ts        # shared ts-morph helpers
```

`src/services/code-generator.ts` can become a re-export barrel or be deleted after migration.

## Shared helpers (`helpers.ts`)

Create small helpers for the constructs that appear repeatedly. These are thin wrappers around `ts-morph` builders to keep the generator code readable.

```ts
import { SourceFile, VariableDeclarationKind, Writers } from "ts-morph";

export const addConstExport = (
  sourceFile: SourceFile,
  name: string,
  initializer: string,
  type?: string,
): void => {
  sourceFile.addVariableStatement({
    isExported: true,
    declarationKind: VariableDeclarationKind.Const,
    declarations: [{ name, type, initializer }],
  });
};

export const addTypeAlias = (
  sourceFile: SourceFile,
  name: string,
  type: string,
  isExported = true,
): void => {
  sourceFile.addTypeAlias({
    isExported,
    name,
    type,
  });
};

export const quoteKey = (key: string): string =>
  /^[A-Za-z_$][A-Za-z0-9_$]*$/.test(key) ? key : Writers.objectKey(key);
```

`ts-morph` accepts initializer and type values as **strings** in many places, which means simple object literals can be written inline using `JSON.stringify` or `Writers.object` when convenient. This dramatically reduces boilerplate compared to building every AST node by hand.

## Converting `generateRuntime`

### Step 1: prepare the source file

Create a `SourceFile` with the generator comment header and conditional import:

```ts
sourceFile.addStatements("// This file is generated by PAC. Do not edit manually.");

if (hasUnknownEventFields) {
  sourceFile.addImportDeclaration({
    isTypeOnly: true,
    moduleSpecifier: "@polar-sh/sdk/models/components/eventmetadatainput.js",
    namedImports: ["EventMetadataInput"],
  });
}
```

### Step 2: emit runtime helper types

If there are event definitions, add the helper type and function:

```ts
sourceFile.addTypeAlias({
  isExported: true,
  name: "DefinedRecord",
  typeParameters: [{ name: "T", constraint: "object" }],
  type: "Partial<{ [Key in keyof T]: Exclude<T[Key], undefined> }>",
});

sourceFile.addFunction({
  name: "omitUndefined",
  typeParameters: [{ name: "T", constraint: "object" }],
  parameters: [{ name: "value", type: "T" }],
  returnType: "DefinedRecord<T>",
  statements: [
    "return Object.fromEntries(Object.entries(value).filter(([, entry]) => entry !== undefined)) as DefinedRecord<T>;",
  ],
});
```

### Step 3: emit resource exports

For each resource kind, add an exported const with an `as const` assertion. The initializer can be built from the sanitized raw object.

```ts
const entries = resources.map((resource) => {
  const sanitized = sanitizeResourceRaw(resource); // keep existing logic
  return `${quoteKey(resource.key)}: ${JSON.stringify(sanitized)},`;
});

const initializer = entries.length === 0 ? "{}" : `{\n  ${entries.join("\n  ")}\n}`;

addConstExport(sourceFile, exportNameByKind[kind], `${initializer} as const`);
```

This still uses `JSON.stringify` for the raw Polar payload, which is acceptable because the payload is plain JSON data. The surrounding TypeScript construct (export, `as const`, property keys) is managed by `ts-morph`.

### Step 4: emit event classes

This is the most complex part. For each event definition, add:

1. A metadata type alias.
2. An input type alias.
3. A class with `declare readonly` fields and a constructor.

```ts
sourceFile.addTypeAlias({
  isExported: true,
  name: `${className}Metadata`,
  type:
    fields.length === 0
      ? "Record<never, never>"
      : `{\n${fields.map((f) => `  ${quoteKey(f.key)}${f.optional ? "?" : ""}: ${eventFieldTsType(f)}${f.optional ? " | undefined" : ""};`).join("\n")}\n}`,
});

sourceFile.addClass({
  isExported: true,
  name: className,
  properties: [
    { name: "timestamp", type: "Date | undefined", isReadonly: true, hasDeclareKeyword: true },
    { name: "name", type: "string", isReadonly: true, hasDeclareKeyword: true },
    {
      name: "metadata",
      type: `DefinedRecord<${className}Metadata>`,
      isReadonly: true,
      hasDeclareKeyword: true,
    },
    // ... other fields
  ],
  ctors: [
    {
      parameters: [{ name: "input", type: `${className}Input` }],
      statements: [
        `const { timestamp, organizationId, externalId, parentId } = input;`,
        `const metadata = omitUndefined(input.metadata);`,
        `if (input.customerId !== undefined) {`,
        `  Object.assign(this, { timestamp, organizationId, externalId, parentId, customerId: input.customerId, memberId: input.memberId, name: ${JSON.stringify(definition.name)}, metadata });`,
        `  return;`,
        `}`,
        `Object.assign(this, { timestamp, organizationId, externalId, parentId, externalCustomerId: input.externalCustomerId, externalMemberId: input.externalMemberId, name: ${JSON.stringify(definition.name)}, metadata });`,
      ],
    },
  ],
});
```

For the input type, use `addTypeAlias` with a string type that expresses the union/intersection shape. Building it as a string is fine because it is still type-checked by `ts-morph` when added to the source file.

## Converting `generateConfig`

### Step 1: accumulate imports

Keep the same `Set<ImportSymbol>` logic. Add a single import declaration at the end or at the start:

```ts
const imports = [...context.imports].sort();

sourceFile.addImportDeclaration({
  moduleSpecifier: "@simonxabris/pac",
  namedImports: imports.map((name) => ({ name })),
});
```

`ts-morph` will place the import at the top of the file automatically.

### Step 2: emit resource declarations

For each resource, add an exported const initialized with `new Meter(...)`, `new Benefit(...)`, or `new Product(...)`:

```ts
sourceFile.addVariableStatement({
  isExported: true,
  declarationKind: VariableDeclarationKind.Const,
  declarations: [
    {
      name: resource.variableName,
      initializer: `new ${kind}(${JSON.stringify(resource.desired.key)}, ${renderSpecAst(resource.desired.spec, context)})`,
    },
  ],
});
```

`renderSpecAst` returns a **string** representing the spec object expression. This is simpler than building a full object-expression AST for nested config specs. The helper functions for prices, filters, and aggregations return strings like `fixedPrice({ amount: 10, currency: "usd" })`.

### Step 3: render config values

For simple JSON values, continue using `JSON.stringify`. For references to other resources, use the variable name directly. For helper calls, build strings:

```ts
const renderMeterFilter = (filter, context): string => {
  const helper = filter.conjunction === "and" ? "and" : "or";
  const args = filter.clauses.map((clause) =>
    isMeterFilterSpec(clause)
      ? renderMeterFilter(clause, context)
      : renderMeterFilterClause(clause, context),
  );
  return `${helper}(${args.join(", ")})`;
};
```

This keeps the existing recursive rendering logic but removes indentation, quoting, and import-accumulation concerns because `ts-morph` handles the top-level structure.

## Effect integration

Wrap the `ts-morph` work in `Effect.try` so failures become `CodeGenerationError`:

```ts
const generateRuntime = (plan: Plan, eventDefinitions: ReadonlyArray<EventDefinition> = []) =>
  Effect.try({
    try: () => {
      const project = new Project({
        manipulationSettings: {
          indentationText: IndentationText.TwoSpaces,
          quoteKind: QuoteKind.Single,
          useTrailingCommas: true,
        },
      });
      const sourceFile = project.createSourceFile("pac.runtime.ts");

      // ... build file

      return sourceFile.getFullText();
    },
    catch: (cause) =>
      new CodeGenerationError({
        message: cause instanceof Error ? cause.message : String(cause),
      }),
  });
```

Do the same for `generateConfig`.

## Testing strategy

1. **Snapshot tests.** Before changing the generator, add snapshot tests for the current output of `generateRuntime` and `generateConfig` using representative inputs. This ensures the `ts-morph` rewrite produces identical output (modulo formatting).
2. **Parse assertions.** After generating, parse the output with `ts-morph` or `oxc-parser` to verify there are no syntax errors.
3. **Type check.** Run `tsc --noEmit` on a fixture config file generated by the new generator to ensure the emitted code is valid TypeScript.

## Migration phases

1. **Add `ts-morph` dependency** and create `src/services/code-generator/helpers.ts`.
2. **Migrate `generateConfig`** first — it is simpler and proves the pipeline.
3. **Migrate `generateRuntime` exports** (prelude, helpers, resource objects).
4. **Migrate runtime event class generation** last.
5. **Delete obsolete string helpers** (`indent`, `renderPropertyKey`, `renderJsValue`, `renderObjectEntries`, `renderExpressionArray`) once both paths are converted.
6. **Add snapshot tests** and verify byte-for-byte or near-byte-for-byte parity.

## Risks and caveats

- **Output formatting may differ slightly.** The TypeScript printer may use different line breaks or spacing than the current hand-written renderer. Snapshot tests should account for this.
- **Performance.** `ts-morph` is fast enough for CLI code generation but heavier than string concatenation. It should not matter for files under a few thousand lines.
- **Dependency size.** `ts-morph` bundles the TypeScript compiler. This increases install size compared to `esrap` or string generation.
- **No Oxc AST.** This plan abandons the Oxc AST entirely. If a future requirement needs Oxc-specific tooling, you would need to parse the generated output with Oxc afterward.

## Summary

The rewrite converts `CodeGenerator` from a string builder into a `ts-morph` source-file builder:

```txt
input (Plan / ImportModel)
        ↓
  sanitize / project data
        ↓
  build SourceFile via ts-morph API
        ↓
  sourceFile.getFullText()
        ↓
  generated string
```

This keeps the current public API, makes the generated code safer and easier to extend, and removes the need for a separate AST printer.
